**Seccion 2: Task vs ValueTask (~10 min, per RESEARCH.md structure)**
- `Task<T>`: siempre allocates en heap, overhead de allocacion
- `ValueTask<T>`: struct, evita allocacion cuando el resultado ya esta disponible (sync path)
- Regla: NO await ValueTask mas de una vez
- Cuando usar cada uno: pregunta frecuente de entrevista
- Usar snippet verificado de RESEARCH.md lines 521-540 como base
- NO challenge standalone — el concepto se integra en challenges posteriores

**Seccion 3: ConfigureAwait(false) (~10 min)**
- Por que importa en librerias: no capturar SynchronizationContext
- Diferencia clave: ASP.NET Core NO tiene SynchronizationContext (vs .NET Framework que si tenia)
- Regla practica: en librerias siempre `ConfigureAwait(false)`, en aplicaciones ASP.NET Core no es necesario pero tampoco dana
- Usar snippet verificado de RESEARCH.md lines 543-558 como base
- **Challenge 2 (APLICACION, estilo negocio per D-10):** "Un servicio de notificaciones con 3 metodos async encadenados necesita ser usado como libreria NuGet. Agrega ConfigureAwait(false) donde corresponda y explica por que en cada caso." Dificultad: media.

**Seccion 4: CancellationToken (~15 min)**
- `CancellationTokenSource` y `CancellationToken`
- `token.ThrowIfCancellationRequested()` para verificar cancelacion
- Propagar el token a toda la cadena de llamadas async
- `OperationCanceledException` y como manejarla vs otras excepciones
- Snippet: crear un CancellationTokenSource con timeout, pasar el token, y manejar la cancelacion
- **Challenge 3 (APLICACION, estilo negocio per D-10):** "Implementar un servicio que descarga un reporte de 3 APIs externas. Si alguna tarda mas de 5 segundos, cancelar todas las operaciones pendientes y retornar error parcial." Dificultad: media-alta.

**Seccion 5: Trampas Comunes (~20 min, per CSHA-04)**
- Subseccion: **async void** — excepciones perdidas, no se puede await, solo para event handlers. Snippet mostrando el problema.
- Subseccion: **.Result / .Wait()** — deadlock en contextos con SynchronizationContext (legacy ASP.NET). En ASP.NET Core no causa deadlock pero sigue siendo mala practica (bloquea thread pool thread). Snippet mostrando el escenario.
- Subseccion: **Task.Run innecesario** — wrapping de codigo ya async, presion innecesaria en thread pool. Snippet mostrando el error y la version correcta.
