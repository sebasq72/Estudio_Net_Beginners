**Section 2: `## Herencia`** (~25 min, per D-06)
- Theory: inheritance syntax, `virtual`/`override` (runtime dispatch based on actual type), `new` keyword (method hiding — compile-time dispatch based on reference type), `sealed` (prevents further inheritance/override for design intent and performance).
- MUST include the interview trap from RESEARCH.md lines 152-170: `Animal a = new Dog(); a.Speak();` vs `a.Move();` showing different output with override vs new. Show BOTH base-type reference and derived-type reference outputs clearly (per Pitfall 1 in RESEARCH.md).
- Challenge 2 (business domain per D-05): "Sistema de empleados" — base class `Employee` with virtual `CalculateBonus()`, derived `Manager` overrides it, `Intern` uses `new` to hide. Student predicts output given different reference types. Pattern 1 collapsible solution.
- Brief `sealed` note: when to use it (framework classes, performance-sensitive code, design intent to prevent further derivation).

**Section 3: `## Polimorfismo`** (~20 min)
- Theory: runtime polymorphism (virtual dispatch), compile-time polymorphism (method overloading), casting (`is`, `as`, explicit cast), pattern matching with types (`switch` expression with type patterns — connects to Phase 1 knowledge).
- Code model: A `Shape` hierarchy with `CalculateArea()` — then process a `List<Shape>` showing polymorphic dispatch.
- Challenge 3 (abstract/technical per D-05 50/50 mix): "Procesador de notificaciones" — given a `List<INotification>`, implement polymorphic processing where Email, SMS, and Push each have different delivery logic. Pattern 1 collapsible solution.

**Section 4: `## Abstraccion`** (~15 min)
- Theory: abstract classes vs concrete classes, abstract methods (contract without implementation), when to use abstract (shared state + partial implementation). Note: full abstract vs interface comparison comes in Plan 02-03.
- Code model: `abstract class PaymentProcessor` with abstract `ProcessPayment()` and concrete `LogTransaction()`.
- Challenge 4 (business domain per D-05): "Disena un sistema de reportes" — abstract `ReportGenerator` with abstract `GatherData()` and `FormatOutput()`, concrete `GenerateReport()` that calls them in order (Template Method preview). Pattern 1 collapsible solution.

**Section 5: `## Resumen: Puntos Clave para la Entrevista`** (per Pattern 2)

  4. Para que sirve sealed?
  5. Diferencia entre polimorfismo en tiempo de compilacion y de ejecucion?
  6. Cuando usarias una clase abstracta? (brief — full answer in 02-03)
